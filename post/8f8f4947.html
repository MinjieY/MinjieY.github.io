Multi-Module File Auto-Upload Tool — An RPA Desktop Application Based on Selenium + PyAutoGUI

Project Background

Automotive supply chains involve multiple tiers with severe information silos. Upstream suppliers’ inventory and order data are difficult to synchronize in real time, resulting in low manual processing efficiency and delayed risk detection. The research paper Cluster Inventory Data Integration and AI Intelligent Governance in Automotive Supply Chains proposed an API integration + AI big data analytics intelligent inventory management solution.

This project is a practical tool derived from that research: SupplyAutoUpload handles the RPA automation segment of batch uploading Excel data to the SupplyOne supply chain management platform — bridging the data entry gap during the phase where upstream and downstream systems have not yet completed direct API integration, covering over 500 suppliers.

Business context article: Cluster Inventory Data Integration and AI Intelligent Governance in Automotive Supply Chains — Shanghai Supply Chain Development Promotion Association

Project Introduction

A desktop RPA automation tool based on Selenium + PyAutoGUI for batch uploading supplier part inventory, sub-tier part inventory, and raw material arrival plan Excel data to the SupplyOne Supply Chain Management Platform.

GitHub: https://github.com/MinjieY/SupplyAutoUpload

Supply Chain Inventory Platform: https://supplyone-stg.ap1.covapp.io/#/login

Features

  • Three Business Module Support
    • Supplier Part Inventory (/ground/supplierStock)
    • Sub-tier Supplier Part Inventory (/ground/2bStock)
    • Raw Material Arrival Plan (/ground/2bStock)
  • Fully Automated Workflow
    • Auto-launch Edge browser and login to SupplyOne platform
    • CAPTCHA display with manual input
    • Auto-navigate to target pages and click upload buttons
    • Use PyAutoGUI to control system file dialogs for file path paste-based upload
    • Upload result judgment with failure screenshots preserved
  • Scheduled Tasks
    • Each module supports independent upload scheduling (minute/hour/day/week)
    • File modification time deduplication to avoid redundant uploads
  • Graphical Interface
    • Tkinter desktop GUI with multi-tab support
    • Real-time log panel with per-module filtering
    • Progress bar and status indicators
  • Auto-Start on Boot
    • Supports Windows registry-based auto-start configuration
  • WebDriver Auto-Management
    • Auto-detect Edge browser version and download matching msedgedriver

Project Structure

Design Logic

Overall Architecture

The program adopts a single-class MVC hybrid pattern, with all logic centralized in the MultiUploadApp class, using Tkinter as the view layer and multi-threading for concurrent control and non-blocking UI. The system is divided into the following core subsystems:

1. Dependency Self-Check & Auto-Install

On startup, check_dependencies() checks whether selenium, pyautogui, pyperclip, and Pillow are available. If missing, they are auto-installed via pip from the Tsinghua mirror using subprocess, enabling direct execution on machines without pre-installed environments.

2. Logging System Design

A custom LogHandler class inheriting logging.Handler bridges Python’s standard logging output to GUI Text widgets via a message queue + Tkinter after timer-based async refresh pattern:

  • emit() pushes log messages into a queue, deferred refreshes via root.after(100, process_queue)
  • process_queue() batch-consumes messages from the queue and writes them to Text widgets
  • Supports enable/disable control to prevent writing to destroyed widgets after window closure
  • Each module has an independent log Tab; the global log Tab aggregates all output

3. Multi-Module Management Architecture

Three business modules are uniformly configured through a MODULES list, with each module owning independent data structures stored in the self.module_widgets dictionary:

  • Each module independently configures URL, file directory, and scheduling parameters
  • Module panels support collapse/expand (toggle_module)
  • Top navigation bar provides quick jump to specific modules (_scroll_to_module)

4. Configuration Persistence

All module configurations (URL, path, scheduling parameters) and global settings (login URL, username, password) are persisted via app_config.json:

  • save_config() / save_module_config() auto-saves on any setting change
  • load_config() restores previous configuration on startup
  • Configuration structure is clearly layered: global holds global settings, each module key holds module-specific settings

5. Browser Driver Management

Edge WebDriver management involves three key steps:

a) Version Detection: Query Windows Registry for Edge browser version number (HKLM\SOFTWARE\Microsoft\Edge\BLBeacon → version), then match and download the corresponding driver from https://msedgedriver.azureedge.net/.

b) Driver Initialization: Use selenium.webdriver.Edge to create browser instances, configured with detach option to prevent automatic browser closure on program exit, and user-data-dir for persistent browser state.

c) Thread Safety: Use threading.Lock to protect self.driver read/write operations (get_driver_safe / safe_driver_quit), preventing crashes from concurrent multi-thread access to the browser object.

6. Login Flow Design

Login adopts a non-blocking async pattern, executed in a background threading.Thread:

Key design points:

  • CAPTCHA images rendered on Tkinter Canvas via PIL.ImageTk.PhotoImage
  • threading.Event (captcha_event) used for inter-thread synchronization and waiting
  • All module “Execute” buttons only become available after successful login to prevent pre-login upload attempts

7. Upload Flow Design

The upload flow is the core automation logic, adopting a step-by-step execution + checkpoint pattern:

Why PyAutoGUI instead of Selenium for file selection?

Selenium cannot directly interact with native OS file selection dialogs (except <input type="file">), and SupplyOne’s upload button triggers a system-level file dialog. Therefore, PyAutoGUI is used to simulate keyboard operations (Ctrl+L → paste path → Enter) to complete file selection.

8. File Deduplication Mechanism

File modification time-based deduplication via log_upload_result() and is_file_already_uploaded():

  • After each successful upload, record filename, modification time, and module name in upload_logs/upload_results.log
  • Before upload, read the log file to check if the current file’s modification time matches the last recorded one
  • Skip upload if matched, avoiding redundant submissions of the same data

9. Task Scheduler Design

Each module has an independent timer implemented via threading.Timer:

Key design:

  • scheduled_run flag distinguishes manual triggers from scheduled triggers; scheduled runs don’t pop up dialogs
  • User can cancel scheduling at any time by clicking “Disable Schedule”
  • cleanup() cancels all active timers on program exit

10. User Interruption Mechanism

stop_requested flag + check_stop() checkpoint pattern:

  • User clicks “Stop” → sets stop_requested = True + calls safe_driver_quit()
  • check_stop() is called between each critical step of the upload flow
  • If flag is True, throws exception to terminate current flow
  • Exception caught by outer try/except, gracefully cleaning up state

11. Auto-Start on Boot Implementation

Implemented via Windows Registry key HKCU\Software\Microsoft\Windows\CurrentVersion\Run:

  • Enable: Write program EXE path
  • Disable: Delete corresponding key value
  • Uses winreg standard library, no third-party dependencies required

Usage Guide

  1. After launching, set the target URL and Excel file directory for each module
  2. Click “Execute” — if not logged in, the login flow will be automatically guided
  3. View the CAPTCHA image in the GUI and enter the CAPTCHA to complete login
  4. The program automatically completes page navigation and file upload
  5. Monitor real-time upload progress and results for each module in the log panel
  6. Set the schedule interval and unit, then click “Enable Schedule” to start scheduled uploads

Notes

  • Do not manually operate the browser during upload to avoid interfering with the automation flow
  • If upload fails, check failure screenshots in upload_logs/screenshots/
  • WebDriver version must match the Edge browser version; the program auto-detects and downloads
  • File modification time deduplication relies on upload_logs/upload_results.log; modify file content first to re-upload the same file
